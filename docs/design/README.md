# Design documents

Each feature gets a design document here **before** any code is written. A
design doc explains why the feature is needed, what the public API looks like,
how it fits the rest of microfmt, and what was deliberately left out. Reviewing
the design first is cheaper than reviewing (or rewriting) a finished
implementation.

| [lexer-languages.md](lexer-languages.md) | Implemented |

Status values: *Proposed* (awaiting approval), *Accepted* (implementation may
start), *Implemented* (links to the user guide), *Rejected*.
